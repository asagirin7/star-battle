# Star Battle ✦

スマホで遊べる、日本語の Star Battle。各行・各列・各色のエリアに星を1つずつ置き、星同士は斜めを含めて隣接させないロジックパズルです。

- 6×6 / 7×7 / 8×8と隠し9×9。次の盤面を選ぶたび、その場で新しい盤面を自動生成。固定の盤面数に上限はありません。コンパクトな色エリアに加えて、盤面の縦・横・両方向を横断する形も生成します。
- 全盤面でエリアの連結性と解の一意性を確認し、既存の盤面と重複しない盤面をDBに保存。
- **6〜8×8は残機3つ × 盤面倍率がスコア**。誤った場所に星を置くと残機が1つ減ります。
- 隠し9×9は8×8の右側にある透明な44pxのボタンから選択。残機は1つで、1ミス即ゲームオーバー。ノーミスクリアは固定100点。エリアは各3マス以上・2行2列以上に広がる連結形状で、一意解を保証します。
- 9×9の「8×8相当の難易度にする」で解きやすい出題に切り替えられます。各色2マス以上・2マスの色エリアを2つ以上含め、縦横に広がる制約を緩めます。簡単モードは固定50点、難しい9×9は100点です。どちらも1ミスで終了し、難しい9×9へも戻せます。
- 6×6は1倍、7×7は2倍、8×8は3倍。ノーミスで3/6/9点、1ミスで2/4/6点、2ミスで1/2/3点です。3ミスでゲームオーバーになり、その盤面は0点です。
- クリアするたびにスコアを累計し、ランキングに反映。遊ぶほど積み上がります。大きい盤面ほど多くのポイントが得られます。
- 正解の星・ミス数・残機・クリアをサーバーで判定・保存。リロード、メモを戻す、複数タブ、通信の再送でも残機が復活したり二重加点したりしません。
- FastAPI + SQLAlchemy + Alembic + PostgreSQL。フロントエンドはHTML/CSS/JavaScriptで、ビルド不要。

## 操作

トラメリア版と同じく、1回タップ（クリック）で × メモを付け外し、同じマスを素早く2回タップすると ★ を置きます。空白からドラッグすると通ったマスに × を付け、× からドラッグすると消します。ドラッグ全体を1手として戻せます。右クリック、またはキーボードの Enter でも星を置けます。Space は ×、矢印キーは移動、Ctrl / Cmd + Z はメモを戻す操作です。

正解の星は固定されます。「メモを戻す」「メモを消す」はメモだけに作用し、ミスと残機は変わりません。「自動で×」をONにすると、星を置いた直後に、同じ行・列・エリアおよび隣接マスに × が付きます。サーバーの正解判定を待ちません。誤った星だった場合は、その星に由来する仮の × だけを戻し、手で編集したメモや別の星の × は保ちます。この設定はブラウザに保存します。ゲームオーバー時は盤面中央の「NEXTゲーム」から次へ進めます。

マスは縦横均等の正方形で、× や ★ によって大きさは変わりません。盤面内での操作ではページのスクロールやダブルタップ拡大を抑制します。通信待ちでもメモや後続の星操作を受け付け、星の判定は順番に送信します。通信失敗時は「通信を再試行」で同じ操作IDから再開できます。

リロードすると難易度ごとの最新の盤面に戻ります。クリア済み・ゲームオーバーの盤面も次の盤面へ進むまでは保持します。途中のメモと未送信の星操作はlocalStorage、確定した星と残機はDBに保存します。盤面の切り替えは、保留中の星の判定が完了してから行います。

## Kamui にデプロイ

[Kamui Python 構成](https://docs.kamui-platform.com/ja/gui/apps/python.html)に従い、リポジトリルートを実行ディレクトリにしてください。資料の `python/main.py` の例に対し、本リポジトリではルートで `python main.py` を実行する構成です。

| 設定 | 値 |
|---|---|
| 実行ディレクトリ | リポジトリルート |
| セットアップコマンド | `pip install -r requirements.lock` |
| 起動前コマンド | `alembic upgrade head` |
| アプリ起動コマンド | `python main.py` |
| Python | 3.12以上 |
| ヘルスチェック | `/health` |

1. 公開リポジトリを接続し、Python アプリを作成。
2. PostgreSQL データベースを作成し、アプリで選択。
3. 上記コマンドを指定。HTTPSでは環境変数 `COOKIE_SECURE=true` を追加。
4. デプロイ後、アプリURLからプレイヤー名を登録して遊べます。

`PORT` に従って `0.0.0.0` で Uvicorn を起動します。DB 接続は `DATABASE_URL` を優先し、未指定時は `DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD` を使用します。どちらもない場合は開発用 SQLite に接続します。本番の記録には PostgreSQL を利用してください。

`.env.example` は設定例です。アプリは `.env` を自動読込しないため、環境変数として設定してください。

既存版からは同じ `alembic upgrade head` で更新できます。プレイヤーとクリア履歴を引き継ぎ、履歴の盤面サイズとミス数から新しい倍率で得点を再計算します（旧固定盤面も対象）。二重に倍率を掛けることはありません。旧固定盤面の途中盤面は、新しい自動生成の盤面へ切り替わります。

## ローカル起動

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
alembic upgrade head
python main.py
```

http://localhost:8000 で開きます。SQLite は `star-battle.db` に保存します。

## プレイヤーと記録

プレイヤーは推測困難なトークンを HttpOnly / SameSite=Strict Cookie に保存し、DBにはそのハッシュのみを記録します。名前は識別子ではないため同名も登録できます。パスワードやメールは不要です。**別端末への引継ぎ・Cookie削除後の復旧には対応していません。** ランキングには名前と累計スコア・クリア数が公開されます。

履歴の時間は盤面を開始してからクリアまでの実時間で、閉じている間も含みます。速度ボーナスはありません。ランキングはデイリーと累計を切り替えられます。デイリーは日本時間の当日0時〜翌日0時にクリアした獲得ポイントを集計し、0時に更新します。各ランキングは対象期間のスコア、クリア数、プレイヤーIDの順。上位100人と自分の累計スコアを表示します。

難易度は盤面サイズによる区分です。盤面は解の一意性を検証し、答えはブラウザへ送りません。生成には時間制限を設けており、時間内に作成できない場合は再試行を案内します。カジュアルなゲームを想定しており、自動解答や複数アカウントの抑止は含みません。

APIテストはサイズ倍率と残機別の得点・3ミスで終了・連続出題と累計・一意解とエリア連結性・再送・他人のゲームの拒否を検証します。ブラウザテストは320/390/1280pxでメモ操作、ミスと確定した星の復元、クリア、ランキング、次の盤面、ゲームオーバーを確認します。操作テストはスマホの実タッチイベントで、単/ダブルタップ、ドラッグ塗り/消し/取消、マスの座標と正方形の維持、通信遅延中の入力、自動×、盤面上のNEXTを検証します。即時反映テストはサーバーの返事を止め、自動×の先行表示、誤配置由来の×だけの巻き戻し、手動メモと消した×・Undo・再開の保持を検証します。描画テストは600msの通信遅延下で各フレームを記録し、星の色・濃さ・背景・表示が確定まで変わらず、未変更の残機・スコアDOMも置換されないことを確認します。並列検証は8件の同時送信で残機・単回加点を確認します。CIではPostgreSQLを使います。

## アカウント・端末間の引き継ぎ・盤面の共有

画面上部の「ログイン / 引き継ぎ」から、現在のゲスト記録をログインID（英数字・_、3〜32文字）とパスワード（10〜128文字）に紐付けられます。Player ID・得点・クリア履歴・途中のゲームを保持し、この端末の既存のバツ・旗も登録時にサーバーへ移します。別端末では最初の名前入力画面の「登録済みのアカウントでログイン」を使用します。直近の盤面を再開し、別難易度の途中盤面も難易度ボタンから開けます。ゲスト記録を既存アカウントへ統合する機能はありません。

パスワードはランダムsalt付きscryptで保存します。ログインごとに独立した30日有効のHttpOnly/SameSite Cookieを発行し、ログアウトはその端末だけを失効させます。パスワード変更は現在のパスワードで確認し、他端末を再ログインにします。メール送信やパスワード再発行機能はないため、登録時にパスワードの保存を案内します。ログイン試行の制限はDBに保存します。

ログイン中のメモは変更セルだけを送信し、サーバーで他のセルの変更とマージします。同じセルを複数端末で編集した場合は後に保存された値を採用します。画面復帰時と10秒ごとに星・残機・メモを更新します。オフライン時は端末に残して通信回復後に送信します。未送信の星を持つ端末は通信回復後の再送が必要です。

「盤面を共有」は常に共有URLと開けるリンクを表示します。「URLをコピー」はClipboard APIと従来のコピー処理を順に試し、両方を使えない環境ではURL選択とリンク長押しでの手動コピーを案内します。端末の共有メニューは別ボタンから開けます。URLは `/?p=<puzzle_id>` で、ログイン前にサイズと得点を確認できます。共有されるのは盤面だけで、解答・プレイヤー情報・星・メモは含みません。相手の挑戦は独立し、同じプレイヤーが同じ盤面を開き直す場合は既存の挑戦を再開します。クリア済みの盤面は再加点しません。

`007` migrationはaccounts/login_sessions/auth_limits/game_memosを追加し、既存Player/Game/Clearを変更しません。`scripts/account_sharing_smoke.py` は2端末の登録・ログイン・再開・旗/バツ・オフライン後のマージと、第三者が共有URLで独立して遊べることを確認します。公開環境でも得点を付けずに実行できます。


ゲームオーバー表示の「盤面を見る」は表示だけを閉じ、終了盤面を残します。再読み込み後も同じ終了盤面を確認でき、次へ進む操作は別に行います。

所有者用の `scripts/merge_players.py` は既定で読み取り専用です。統合には `--apply --expected-source-name <name>` が必要で、宛先は指定したログインIDから解決します（`--expected-target-id` でIDも固定可能）。独立したログインを持つ移行元や統合の連鎖は拒否します。移行前のGame/Clearと名前を008の監査記録へ保存し、同じ盤面のクリアは最高得点・同点なら早いクリアを残して重複加点を防ぎます。古いゲスト端末は取り消し可能な30日セッションに移し、パスワード変更時の全端末失効にも従います。公開APIから統合を実行する機能はありません。

人間の所要時間に基づく盤面難易度の研究は [研究メモ](docs/research/human-difficulty.md) にまとめています。人の時間との相関はまだ測定しておらず、公開版の配点や出題条件には適用していません。

クリア後は盤面中央またはツール欄の「クリア結果を共有」から、公式のクリア秒数と得点を含む結果テキスト・URLを再共有できます。URLは `/?p=<puzzle_id>&c=<clear_id>` で、相手は結果を確認して同じ盤面に挑戦し、自分の結果をさらに共有できます。秒数・得点はサーバーに保存した記録を使い、URLに追加した値では変更できません。

`scripts/result_sharing_smoke.py` は共有→クリア→再共有、コピー不可時の操作、不正な結果URLを検証します。クリアによる加点を伴うため、localhost / 127.0.0.1 のローカルサーバー専用です。公開環境では実行できません。

## .d 特別盤面

[特別盤面を遊ぶ](https://star-battlem7kqdh9n.kamui-platform.com/?p=d0d0d0d0d0d04d0da0d0d0d0d0d0d0d0) は領域の形で `.d` を表した9×9盤面です。元画像の色には合わせず、通常盤面と同じ9色で各領域を区別します。通常の9×9と同じ残機1・ノーミス100点です。

固定IDと盤面は `data/special_boards.json` に保存し、009 migrationで一意解・領域連結・非分岐の論理解法を検証して登録します。通常のランダム生成には混ぜません。登録コマンド `python scripts/install_special_boards.py` も同じ内容を二重登録せず、既存の盤面・プレイ履歴は変更しません。
